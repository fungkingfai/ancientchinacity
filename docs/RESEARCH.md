## 1. 研究目的與方法

### 1.1 目的

《華夏古城》是「中國古代版 SimCity」：72×72 地圖、方格道路、20+ 種建築、可進入室內、市民個體模擬、物流與生產鏈、財政、晝夜四季晴陰雨雪、存檔。本研究的目標不是抄襲，而是回答四個問題：

1. 同類遊戲的**核心循環**如何讓玩家在 10 分鐘內理解「下一步該做什麼」？
2. **物流與生產鏈**要用多深的模擬，才既好玩又能在瀏覽器 60fps 下實作？
3. **市民需求／幸福度／財政**的數值如何互相牽制，避免「錢多到無意義」或「一開始就破產」？
4. **時間、天氣、節慶、建築室內**如何服務主題（中國古城）而不是純裝飾？

### 1.2 取樣與選擇理由

| 遊戲 | 為何選它 |
|---|---|
| Emperor: Rise of the Middle Kingdom（2002） | 唯一的**中國古代**經典城市建造，題材、建築分類、風水、節慶、貿易皆可直接對照 |
| Pharaoh（1999）／Pharaoh: A New Era（2023） | 同引擎血緣的古典城市建造；**walker 服務系統、住房進化、糧倉物流**是本研究最完整的教材 |
| Anno 1800（2019） | 現代**生產鏈＋分層需求**標竿；需求解鎖、吸引力、生產統計 UI 可借鏡 |
| Banished（2014） | 無貨幣的**生存型**城市建造；冬季儲糧、職業分配、人口老化帶來壓力設計 |
| Manor Lords（2024） | 中世紀**有機建造＋稅收＋季節**；驗證「無網格／低網格」與稅種設計 |
| Foundation（2019 EA／2025 正式） | **無網格有機都市**與紀念碑建造；驗證放寬建造限制能帶來的放鬆感 |
| 江南百景圖（2020） | 中國古風手遊標竿；營造分類、繁榮度解鎖民居、神像光環、環境值、生產鏈 |

## 2. 逐款研究

### 2.1 Emperor: Rise of the Middle Kingdom《皇帝：龍之崛起》（2002）

**基本資料**
- Impressions Games／BreakAway Games 開發、Sierra 發行；City Building 系列第六作，也是系列最後一款 2D 精靈引擎作品、首款多人遊戲；時代橫跨夏至宋金（西元前 2033～1234 年），共 7 個戰役。[S1][S2]

**核心循環**
- 每關最基礎任務是維持城市：餵飽人民、保持健康、免於災害；食物、基本物資與服務充足，城市就會成長。進一步要**管理貿易與稅收**以支撐擴張；同時向祖先英雄與儒釋道人物獻祭，英雄滿意會來訪賜福，發怒則降災。[S1]
- 玩家還要回應**其他城市的要求與好感**（與前作只討好君主不同）、防禦入侵、建造大型紀念碑（長城、大運河、兵馬俑等）。關卡目標包括：生產指定物資、征服城市、達到人口、建造紀念碑。[S1]

**建造與城市**
- 建築以「部會」分類：平民住宅／貴族住宅、農業、工業、商業、治安、政務、娛樂、宗教、軍事、美學、紀念碑。[S4]
- **風水**是選址系統：五元素（土、金、水、木、火）對應地形（岩石／峭壁＝土、礦脈＝金、草地＝水、樹木＝木、旱地＝火；沙灘等為中性）。建築與地形「相生」為和諧（綠色足跡）、相剋為不吉（黃色）；全城和諧建築比例決定風水評級（100% = Perfect Harmony，最低 China Shamed）。[S5]
- 住宅會依「食物品質＋物資＋服務」升級：平民住宅 Shelter→Hut→Plain Cottage→Attractive Cottage→Spacious Dwelling→Elegant Dwelling→Ornate Apartment→Luxury Apartment；貴族住宅 Modest Siheyuan→…→Heavenly Compound（人口 5→25）。升級需求包含水井、祖祠、麻布、樂師、針灸師、佛道建築、茶、陶器、戲劇等；等級越高**稅率乘數**越高（1～24）。[S6]
- 食物有「品質」：磨坊（Mill）中的食物種類數＋鹽＋香料決定 Bland／Plain／Appetizing／Tasty／Delicious；市場的食物舖派人到磨坊取貨，再配送至住宅。[S6][S10]
- 住宅區設計是核心技巧：以**環狀道路＋路障**把服務行者（walker）留在住宅區內，提高服務覆蓋效率；住宅圍牆可阻擋負面景觀、城門可設定放行哪些行者。[S10]

**物流／生產**
- 市場廣場（Market Square）是商業樞紐：食物舖從磨坊取貨、市場僱員配送；娛樂（樂師、雜耍）由學校出發到市場廣場表演，再由「報幕員」把娛樂覆蓋帶進住宅。[S10]
- 產業按部會分：農業（農田、果園）、工業（窯、冶鐵、織造等）、商業（貿易站／碼頭）。各城市有不同特產，缺料需進口。[S1][S4]
- 貿易：每個貿易夥伴需要專屬貿易站或碼頭；陸路商人每次最多買／賣 8 單位，船運 12 單位，每年有上限；**玩家可自訂進出口價格**（最高可達帝國標準價 2 倍），價格過高會影響對方城市好感；鑄幣廠可提高售價約 4%。[S9]

**財政**
- 稅收按月逐棟住宅計算：`人口 × 稅率乘數（1～24，依住宅等級）× 稅率`。稅率選項：0%／3%／6%／9%／12%／15%／18%。房屋周邊景觀值（desirability）高於該級最低需求時，稅率可再增加，最多 +2.5%。付款會四捨五入到整數。[S7]
- 工資率影響勞動供給：以 Normal 難度為例，工資「一般」時只有 42% 平民投入勞動、Very High 時 47%；月薪支出＝就業人數 × 年現金 ÷ 12。研究結論：在景觀良好的前提下，**同時提高稅率與工資**比低稅低薪更賺（因為勞動供給與稅基一起上升）。[S7]

**市民／需求／幸福**
- 住宅升級需求是「食物品質＋物資＋服務」的組合；若失去物資／服務／景觀，房屋會**降級**並可能趕走居民（有緩衝期）。[S6][S10]
- 疾病、火災、犯罪是風險來源，需草藥師、針灸師、巡檢塔、水井等服務；貴族住宅人口少但稅高，平民住宅提供勞動力。[S6][S10]

**時間／天氣／節慶**
- 每年 2 月（人口 > 100 時）可辦**新年節慶**：花費與食物**隨人口縮放**：`現金 = (人口+10)/5，向下取整到百位；食物 = 現金 × 2`（例：4200 人口 → 800 現金＋1600 食物）。舉辦提升民心，禁止則下降。[S8]
- 年度生肖加成：在生肖年辦節慶可選「禮物／建築四分之一價／產量加倍／軍事加成」，效果依當年五行元素而不同。[S8]

**UI／顧問**
- 介面以部會分頁＋顧問（Overseers）呈現城市問題；有各種覆蓋層（overlay）檢視住宅需求、風水、景觀等。[S1][S4][S5]

**可借鏡機制**
- R-EMP-1：**建築以「部會／類別」分頁**，與本作 `CATEGORY_INFO` 六分類（民居／生產／倉儲／商業／民生／裝飾）一致，可再補「衙門＝政務」的定位。
- R-EMP-2：**選址加成**（風水→本作的沃土／林地／丘陵／臨水加成）是低實作成本、高辨識度的策略層。本作 v1 用既有地形加成；v1.1 可加「風水景觀值」覆蓋層。
- R-EMP-3：**服務覆蓋＋住宅升級**。本作 v1 不做 8 級住宅進化，但可保留「水井／寺廟／學堂／茶館在半徑內 → 幸福度加成」的簡化版。
- R-EMP-4：**節慶成本隨人口縮放**（本作目前固定 300 兩，見 GAME_DESIGN §13 建議調整）。
- R-EMP-5：**稅率乘數隨住宅等級提升**，可作為本作「宅院／瓦房 vs 茅屋」的稅基差異（v1.1）。
- R-EMP-6：**貿易站／碼頭出口＋可調價格**；本作 v1 只做碼頭出口（固定參考價），v1.1 可做價格調節。

### 2.2 Pharaoh（1999）／Pharaoh: A New Era（2023）

**基本資料**
- Impressions Games 開發、Sierra 發行；與 Caesar III 同引擎與設計原則；玩家管理古埃及城市的糧食、就業、健康、疾病／災害／戰爭防護；有戰役與自由建造模式，2023 年由 Triskell Interactive／Dotemu 推出重製版《Pharaoh: A New Era》。[S11]

**核心循環**
- 劃設住宅區 → 移民遷入並自行升級住房 → 提供食物、物資、服務與景觀 → 住房升級帶來更多人口與稅收 → 支撐紀念碑、軍隊與貿易。[S11][S12][S13]

**walker 服務系統（本作最重要的對照）**
- 多數非住宅建築會產生 **walker**（NPC），沿鄰近道路行走；walker 經過的住宅（道路 2 格內）獲得該建築的服務。分兩類：
  - **隨機行者（random walkers）**：服務類（消防、建築師、警察、市場配送員、醫生、祭司、圖書館員等），遇岔路隨機轉彎，走完最大步數後返回。
  - **目的行者（destination walkers）**：有固定目的地（移民、市場採購員、推車送貨員、軍隊、藝人）。送貨行者只能送到有道路連接且能收貨的建築；取貨行者可越野。
- 路障（roadblock）可擋隨機行者、不擋目的行者；玩家利用「強制步行（forced walker）」把服務行者繞行整個住宅區。[S12]
- 服務建築會顯示紅色（消失點）與綠色（生成點）方格；住宅必須在道路 2 格內才吃得到服務。[S12]

**住房進化**
- 住房有 20 級：Crude Hut → … → Palatial Estate；升級需要景觀值門檻＋娛樂點數＋服務（水井、1 種食物、神祇、娛樂、陶器、醫生、啤酒、法院、學校／圖書館、奢華品、2～3 種食物等）。房屋會隨等級從 1×1 成長到 2×2、3×3、4×4；失去服務會降級（有緩衝期）。[S13]
- 稅收：`年稅 = 住戶數 × 稅率乘數 × 城市稅率 × 6`；稅率乘數依住房等級而異（例：Common Residence 為 3）。[S13]

**物流／倉儲（本作可借鏡的關鍵）**
- **市集（Bazaar）**：採購員（目的行者）從糧倉／倉庫取貨，配送員（隨機行者）沿路把貨賣給住宅；市集需至少約 200 單位庫存才會派採購員；最多 2 名採購員（食物／物品各一）；景觀好的市集有 2 名配送員。[S12]
- **糧倉／倉庫**：每棟 3200 單位（8 格 × 400，不可混放同一格）；糧倉只收食物、倉庫收全部；每種資源可設 Accept／Get／Empty／Discard 與容量比例；推車行者（cart pusher）負責搬運，Get 可越野、Empty 只能走道路。[S12]
- **食物**：狩獵、漁撈、氾濫平原農耕（每年尼羅河氾濫、需灌溉渠道）、草地農耕（一年一～兩收）、牧場、進口；肥沃度是產量乘數，灌溉提升肥沃度。[S12]

**市民／幸福**
- 住房等級本身即是「需求滿足」的可視化；景觀值由宗教建築、花園、廣場提升，由工業、商業、軍事建築降低。[S12][S13]
- 失業、稅率、工資、食物種類、娛樂、宗教影響城市評價（sentiment）與移民。[S12][S13]

**時間／天氣**
- 尼羅河每年氾濫（2～4 個月）影響氾濫平原農田；季節與年週期是生產規劃核心。[S12]

**UI／建造**
- 2D 等角、固定縮放但可 90° 旋轉；大量鍵盤快捷鍵；顧問（Overseers）與覆蓋層；訊息面板、問題點循環跳轉。[S11][S12]

**可借鏡機制**
- R-PHA-1：**兩段式物流**（生產者→倉庫、倉庫→市集）比「生產者直接送消費者」更清楚，也更能讓物流可視化。本作採用：生產者→倉庫→市集／服務建築。
- R-PHA-2：**倉儲容量與分類限制**（糧倉只收糧、貨棧全收）→ 本作已有 `storage.accepted`，直接沿用。
- R-PHA-3：**建築需道路才提供服務**，是本作 `connected` 的設計來源；但本作用「服務半徑＋每日結算」取代隨機行者，降低 CPU 與實作風險。
- R-PHA-4：**住房升級**是長期目標感來源。本作 v1 先以「瓦房／宅院解鎖」承擔進化感；v1.1 再考慮住宅等級。
- R-PHA-5：**市場配送員/採購員分工** → 本作搬運工（Cart）分 pickup／deliver 兩階段，市集另外每日向倉庫提貨。
- R-PHA-6：**糧倉與市場必須真的被填滿**，是玩家「物流沒接通」的主要挫敗點；本作 UI 必須顯示市集貨架存量與「缺貨」原因（資訊回饋是本作要勝過 Pharoah 的地方，對照 Banished 的批評）。

### 2.3 Anno 1800（2019）

**基本資料**
- Ubisoft Blue Byte 開發、Ubisoft 發行；Anno 系列第七作，回到歷史題材（19 世紀工業革命），保留城市建造與海戰，新增觀光、藍圖、工業化對居民的影響。[S14]

**核心循環**
- 舊世界城市的需求（農民→工人→工匠→工程師→投資者）驅動生產與供應鏈管理；新世界城市生產舊世界勞動者想要的商品，需要建立貿易航線；另有故事戰役、沙盒、多人。[S14][S15]

**分層需求（本作最值得借鏡的節奏設計）**
- 農民需求：魚、烈酒（Schnapps）、市場；工人：香腸、工作服、學校、酒館；工匠：麵包、罐頭、肥皂、大學、教堂、雜耍劇場；工程師：咖啡、眼鏡、燈泡、銀行、俱樂部、電力；投資者：珠寶、留聲機、香檳、百貨公司、大展覽、世界博覽會。
- 滿足需求並維持幸福度即可升級；公共服務（市場、酒館、學校、教堂）有覆蓋半徑；吸引力（attractiveness）由公共服務、裝飾、文化建築提升，吸引新居民；「生產統計」頁面用於比較產量與消耗。[S15]
- **藍圖模式**：先放半透明藍圖建築規劃城市、不急著花資源，材料齊備後一鍵建成。[S14]

**物流／生產**
- 生產鏈（例）：豬→屠宰場→香腸；羊→羊毛織坊→工作服；麥→磨坊→麵包坊；鯨油→肥皂廠；玻璃→眼鏡；燈絲→燈泡。高階商品需要跨區域（新世界）貿易航線。[S15]
- 工業化會降低吸引力，觀光客帶來收入但討厭污染與動盪。[S14]

**財政／市民**
- 居民升級提供更多收入與勞動力；供過於求比供不應求好；必須平衡各階層勞動力。[S15]
- 吸引力與幸福度影響升級與新居民。[S15]

**UI**
- 頂欄＋生產統計、需求分頁、覆蓋層、藍圖模式、貿易航線管理。[S14][S15]

**可借鏡機制**
- R-ANN-1：**需求分層＋解鎖建築**。本作 `unlockPop` 曲線（15 糧倉→20 市集→30 瓦房→…）就是簡化版；建議把「需求滿足」做成可視清單（食物／日用品／文化），玩家才知道為何人口不漲。
- R-ANN-2：**生產統計／收支報表**。本作財政面板已有月報表；建議加「糧食供需」與「各資源庫存」兩個小區塊。
- R-ANN-3：**藍圖模式**是很好的低風險 v1.1 功能（先規劃道路與建築位置，不扣款）。
- R-ANN-4：**吸引力**可對應本作的涼亭／寺廟／學堂，作為 v1.1 的「城市聲望」而非只加幸福度。

### 2.4 Banished（2014）

**基本資料**
- Shining Rock Software（單人開發）2014 年發行；聚焦「孤立的流放者聚落」之資源管理與生存；被拿來與可持續性、最佳化經濟理論比較。[S16]

**核心循環**
- 玩家指派市民從事建造、捕魚、耕作等職業，市民自行執行；市民有需求（食物、住所等）要滿足才健康快樂；人口來源為生育與遊牧民族加入，市民會老化、死亡；災害有嚴冬、火災、憂鬱、饑荒、人口老化。[S16]
- 沒有貨幣：難度來自資源稀缺與季節規劃（IGN 評論特別指出「以缺乏金錢資源而非金錢來製造難度」）。[S16]

**物流／生產**
- 官方遊戲頁把玩法分為：Build（建造）、Manage（管理工人與庫存）、Craft（加工）、Trade（貿易）、Survive（過冬與災害）、Feed（漁獵／採集／農耕混合）、Relax（放鬆觀賞）。[S17]
- 食物來源需混合（狩獵、採集、農耕、漁業），並在冬天前儲備。[S16][S17]

**市民／需求**
- 市民是「被管理的資源」；人口老化是長期壓力；生產與庫存需要玩家持續監看。[S16]
- 評論批評：**缺乏對玩家行動的回饋**，是此類遊戲最常見的 UX 問題。[S16]

**可借鏡機制**
- R-BAN-1：**冬季前儲糧**是本作四季設計的核心壓力：秋季高產（config 1.25）→ 冬季大跌（0.35）→ 需要糧倉容量與物流。數值見 GAME_DESIGN §8／§13。
- R-BAN-2：**職業分配／勞動力**：本作以市民 `workId`＋建築 `workers` 實作，必須讓玩家看得到「失業／缺工」。
- R-BAN-3：**回饋不足是致命傷**：本作 UI 需明確顯示缺糧、缺工、缺路、缺貨的**原因**（不只數字），並用 toast／面板提示。
- R-BAN-4：**人口老化與死亡**：本作遊戲年僅 84 天，若照真實年齡會幾乎沒人死亡；建議用遊戲日為單位的機率模型（見 GAME_DESIGN §5）。

### 2.5 Manor Lords（2024）

**基本資料**
- Slavic Magic（Grzegorz Styczeń）開發、Hooded Horse 發行；中世紀城市建造＋即時戰術；2024-04-26 搶先體驗，上市前為 Steam 願望清單第一（超過 200 萬）。[S18]

**核心循環**
- 以 14 世紀法蘭克尼亞為靈感；從小型聚落開始，採集資源、管理供應鏈、擴張貿易網絡，同時處理內部凝聚力與外部威脅；五種模式（Rise to prosperity 無戰鬥等）；可調整起始位置、地圖、威脅；第三人稱視角可逛自己的街道。[S18]

**建造**
- 主打**有機城市建造**：道路幾乎都是彎曲的，房屋可在沒有固定分區網格的情況下建造；建築機制模擬真實中世紀城鎮如何受貿易路線與地貌影響；建築需維護才能高效運作；季節帶來不同需求與機會；城堡與防禦工事可建造。[S18]

**市民／幸福**
- 滿意度（satisfaction）受稅收與什一稅影響；民生與環境影響長期發展。[S18]

**可借鏡機制**
- R-MAN-1：**稅種分離**（人頭稅／田賦／商稅）比單一稅率有深度；本作可保留三種稅基並在財政面板列出明细。
- R-MAN-2：**建築維護與環境代價**：本作可用「維護費」承擔，v1.1 可加伐木造成林地減少、採石造成地形改變（worldgen 需預留）。
- R-MAN-3：**第三人稱遊覽**→ 本作的「進入建築室內」是其低成本替代，應強化「逛城市」的沉浸感（室內＋街道走動的市民）。
- R-MAN-4：**季節影響生產與建設**：本作 `SEASON_FARM_BONUS` 已具備，需在 UI 明示。

### 2.6 Foundation（2019 搶先體驗／2025 正式）

**基本資料**
- Polymorph Games 開發／發行；2018 open alpha、2019-02-01 搶先體驗、2025-01-31 正式版；使用自研 Hurricane 引擎。[S20]

**核心玩法**
- 主打**無網格（grid-less）有機都市**：建築可自由擺放，城市像真實中世紀城鎮般蔓延；玩家透過「書」控制遊戲各面向，進度以 tier 解鎖；村民需被指派工作／角色，建築需指派資源；領地可用購買方式擴張；地貌需「塗刷」指定用途；與鄰村貿易是經濟的一部分；設計上刻意放鬆、限制少。[S20]
- 官方頁強調：**有機發展＋紀念碑建造＋資源管理**；居民需求與技能、資源開採與轉化形成複雜互動網；獨特的紀念碑創作工具（可自由設計修道院、教堂、領主宅邸、城堡）；完整 Mod 支援。[S21]

**可借鏡機制**
- R-FOU-1：**放寬建造限制能帶來放鬆感**。本作底層是方格（改動成本高），但可透過「道路拖曳鋪設、建築自動對齊、幽靈預覽」降低操作摩擦，達到類似的順暢感。
- R-FOU-2：**紀念碑／地標**可作為本作進階目標：例如集資建造「鼓樓」「寶塔」「城隍廟」，需要大量資源與時間，完成後提供全城光環（v1.1）。
- R-FOU-3：**居民需求＋技能**：本作 v1 不做技能，但可保留「居民名單＋就業」的個人感。

### 2.7 江南百景圖（2020）

**基本資料**
- 椰島遊戲開發、2020-07-02 上線的古風模擬經營手遊；玩家扮演文徵明，在明朝江南營造城市、安排居民起居工作、探索奇遇。[S22][S23]

**核心循環**
- 營造（居住／生產／娛樂／裝飾）→ 生產資源與銅錢 → 提升繁榮度 → 解鎖民居與人口 → 擴大生產與布局。[S22]
- 建築多數需要**緊靠道路**，道路佔地，玩家要在「最少道路」與「最大建築量」之間取捨；另有神像（灶神、織女、財神等）對特定建築提供 2～3 格範圍加成，成為布局核心。[S22]
- 「環境」值：部分建築（如家具舖）需所在地環境和諧才能升級；和諧綠、一般無色、不和諧紅；可用花草樹木裝飾「淨化」環境。[S22]

**物流／生產**
- 生產鏈環環相扣：農田蔬菜→餐館菜餚；林場原木→鋸木廠木板→造紙廠紙張（供書院產書）；另有漁場、棉花等。[S22]
- 城內固定建築：州府（公告／抓盜賊）、倉庫（存物資）、雕像（生產加成）、客棧（三白酒／物資兌換）、驛站（探險副本）、稅課司（自動收物資與銅錢）、書局、碼頭（運物資與居民）。[S22]
- 貨幣：銅錢（建築產出／任務）與補天石（任務／付費）；銅錢用於升級建築、生產資源、解鎖地圖。[S22]

**市民／繁榮度**
- 普通居民來自民宅建造；特殊居民來自抽卡（士／卿／侯／天四檔），有建造、農牧、製造、理財、冒險五種屬性與天賦。[S22]
- 繁榮度由娛樂與裝飾建築提升；繁榮度達標解鎖新民居，增加人口與勞動力。[S22]

**可借鏡機制**
- R-JNB-1：**中國古風的直觀分類**（居住／生產／娛樂／裝飾）＋「民居→人口→勞動力」的正回饋，正是本作該給玩家的第一印象；本作 `CATEGORY_INFO` 六分類可以再細分圖示與文案。
- R-JNB-2：**繁榮度作為解鎖貨幣**：本作以 `unlockPop`（人口）承擔；v1.1 可加「城市聲望」由裝飾／寺廟／節慶累積。
- R-JNB-3：**神像光環**：本作可轉化為「衙門／寺廟／學堂的服務半徑」；同一概念、降低實作成本。
- R-JNB-4：**環境值**：本作可用樹木／涼亭／水井覆蓋率影響幸福度；v1.1 可加覆蓋層。
- R-JNB-5：**倉庫／稅課司／碼頭**是古風城市必要的設施感；本作已有糧倉、貨棧、碼頭，建議 UI 與模型強化辨識度。
- **不採用**：抽卡、體力、付費加速、好友社交——本作是單機網頁遊戲。

## 4. 綜合設計啟示（給《華夏古城》的 15 條結論）

1. **核心循環要是「可見的正回饋」**：Anno／Emperor／江南百景圖都用「滿足需求→人口或等級提升→解鎖新建築」讓玩家在 2～3 分鐘內看到成果。本作每個遊戲日 30 秒（1×），應讓「鋪路→建茅屋→流民入住→建農田→人口成長」在 5～8 個遊戲日（2.5～4 真實分鐘）內發生。
2. **物流要分段、可視化**：Pharaoh 的「生產者→倉庫→市集→住宅」是本作的正確骨架；不要讓生產者直接賣給市民，否則搬運工、倉庫、市集都失去意義。
3. **容量與分類限制創造決策**：糧倉只收糧、貨棧全收、市集貨架有限——這些限制讓「蓋哪一種倉庫」變成選擇（Pharaoh 的 3200 單位／不可混放亦然）。
4. **市場半徑＋每日結算足以替代 walker**：Pharaoh 的隨機行者很迷人，但對 800 市民＋40 搬運工的瀏覽器遊戲而言成本過高。用「半徑＋每日需求結算」可保留策略感並降低 bug 面。
5. **需求要分層且原因清楚**：Anno 的「需求清單」與 Banished 的「回饋不足」教訓指出：玩家不怕難，怕不知道為什麼。本作必須顯示「食物／日用品／文化」三條需求與各自缺口。
6. **住宅升級是長期黏著劑**：Pharaoh／Emperor 的住房進化是玩家數十小時的目標。本作 v1 以瓦房／宅院解鎖承擔一部分；v1.1 應補「依需求升級」。
7. **稅基分離讓財政有話可說**：Manor Lords 六稅種、Emperor 逐棟稅收，都讓「稅率」不只是單一滑桿。本作 v1 至少分人頭稅、田賦、商稅三項並列在月報表。
8. **節慶成本應隨人口縮放**：Emperor 的新年節慶公式（人口越大越貴）比固定 300 兩合理；否則後期節慶變成無腦 buff。
9. **四季與天氣的意義是「規劃」**：Banished 的冬季儲糧、Manor Lords 的季節生產；本作秋季 1.25 倍、冬季 0.35 倍的設計已具備，需在 UI 提醒玩家秋收後存糧。
10. **天氣要影響「人」而不只是「田」**：雨雪降低移動速度（config 已有），應讓玩家看到市民／搬運工變慢，並在結算時反映到物流延誤。
11. **中國題材的差異化在「制度與風俗」**：風水、衙門、科舉學堂、茶館、節慶、生肖——不是換皮。本作至少要把衙門（稅收加成）、寺廟（民心）、學堂（文化）、茶館／客棧（消費與收入）做出制度感。
12. **建築室內是本作獨特賣點**：同類遊戲幾乎都不能進屋。室內不只是展示，應提供「居民名單／工人名單／庫存／本月收支」等營運資訊，讓玩家有理由走進去。
13. **回饋與提示要用「人話」**：不要只顯示「效率 0.7」，要顯示「糧食不足：市集空了，請檢查糧倉到市集的道路」。
14. **金錢是門檻，不是生存壓力**：本作有 6000 兩開局與稅收，金錢不會像 Banished 那樣致命；真正壓力應來自勞動力、道路、倉儲與民心。數值設計要把錢放在「蓋新東西」而非「活下去」。
15. **控制 scope**：本作是網站小品遊戲，2026 年的設計應以「可實作、可驗收」為第一原則；所有 P2 機制在 GAME_DESIGN 中標為 v1.1，不阻塞整合。

## 5. 明確不採用的設計（避免 scope creep）

| 機制 | 來源 | 不採用原因 |
|---|---|---|
| 隨機行者（walkers）／路障強制步行 | Pharaoh、Emperor | CPU 與 bug 成本高；本作以服務半徑＋每日結算替代 |
| 20 級住房進化、貴族住宅 | Pharaoh、Emperor | 內容量過大；v1 以 3 種民居＋服務加成承擔 |
| 多島嶼／新世界貿易航線 | Anno 1800 | 本作單一地圖；碼頭出口已足夠 |
| 軍事、城牆、即時戰術 | Emperor、Manor Lords | 非本作核心；列為 v2 想法 |
| 無網格有機建造 | Foundation、Manor Lords | 底層資料模型是方格；改動成本高 |
| 抽卡、體力、付費加速、好友社交 | 江南百景圖 | 本作是單機網頁遊戲，不做營運式設計 |
| 六種以上稅種、什一稅、國王稅 | Manor Lords | 對本作玩家過於複雜；v1 三稅基即可 |
| 真實年齡老化（16→60 需 44 遊戲年） | 靈感自 Banished | 本作時間尺度太快，改用機率死亡模型 |

## 7. 研究限制與後續研究建議

1. **手冊與官方數值不可得**：Emperor 原版手冊 PDF 被 Cloudflare 阻擋；本研究中 Emperor 的具體公式（稅收、住房圖表）全部來自 Emperor Heaven 的玩家實測整理，可信度高但非官方。
2. **Emperor 的「天氣」與晝夜**：公開資料著墨不多，本作不宣稱模仿其天氣系統；四季／天氣設計主要參考 Banished 與 Manor Lords。
3. **江南百景圖的具體數值**（如繁榮度門檻）在百度百科中未完整列出，本研究只引用其機制描述；本作不直接移植其數值。
4. **後續可研究**：`Cities: Skylines` 的服務覆蓋與交通模型、`The Settlers` 的物流鏈、`Timberborn` 的水文與季節、`Ostriv` 的有機建造與市場機制；另可研究「城市建造遊戲的 UI 資訊層級」相關 GDC 演講。
5. **本文件的使用方式**：`docs/GAME_DESIGN.md` 的每個系統若標註 R-XXX 編號，即對應本文的研究結論；數值則以 `src/core/config.ts` 為最高依據。
