## 0. 遊戲概述與設計支柱

### 0.1 一句話

> 在山水之間鋪路、墾田、開市、興學、建廟，讓流民成為百姓、讓村落成為古城；你可以走進每一棟屋子，看看住在裡面的人過得如何。

### 0.2 平台與規模

| 項目 | 內容 |
|---|---|
| 形式 | 瀏覽器網頁遊戲（Vite + three.js + TypeScript），單機 |
| 地圖 | 72×72 格，每格 2 世界單位；地形有平原／沃土／林地／丘陵／山地／水域／沙岸 |
| 時間 | 1 遊戲日＝1440 遊戲分鐘＝**30 真實秒**（1×）；1 月＝7 日；1 年＝12 月（約 42 分鐘）🕐 |
| 人口上限 | 約 800 人（效能考量） |
| 目標客群 | 喜歡城市建造、中國古風、輕鬆但有事可做的玩家 |
| 一局長度 | 10～30 分鐘有明顯成長；可存檔續玩 |

### 0.3 設計支柱（所有取捨以此判斷）

1. **看得見的中國古城**：不只是換皮。風水選址、衙門稅收、寺廟香火、學堂文化、茶館客棧、節慶燈會，都要表現在玩法上，而不只是模型。
2. **每一天都有事做，但不逼人**：1 日＝30 秒，玩家平均每 10～20 秒做一個小決策（鋪一格路、蓋一棟房、調整稅率、查看缺口）。暫停永遠可用。
3. **原因要說人話**：任何「數字不好」都必須能追溯到一個玩家看得懂的原因（缺路、缺工、缺糧、缺貨、稅太高、冬天到了）。
4. **物流可視化**：生產→倉庫→市集→民居的每一段都有搬運工在走；倉庫與市集的庫存要能一眼看出。
5. **金錢是門檻，不是生存壓力**：國庫決定「能不能蓋」，真正壓力來自勞動力、道路、倉儲、民心（對照 Banished 的生存壓力與 Anno 的供應鏈壓力）。
6. **室內是特色而非負擔**：每一棟建築都能進去，室內要能回答「這棟建築現在運作得好不好、裡面住著／工作著誰」。

## 1. 核心循環

### 1.1 四層循環

| 層級 | 時間尺度 | 玩家在做什麼 | 系統結算 |
|---|---|---|---|
| **秒級** | 每幀 | 看市民走動、搬運工運貨、天氣變化、建造預覽；滑鼠鋪路／放建築 | 市民移動、搬運工移動、相機、環境 |
| **日級** | 30 秒（1×） | 檢查糧食／人口／民心；補路、補房、補農田、補市集 | 生產、人口遷入／出生／死亡、需求與幸福、物流派遣 |
| **月級** | 3.5 分鐘（1×） | 看月報表、調稅率、決定是否辦節慶、規劃下一批建築 | 稅收、維護費、服務收入、月報表、破產檢查 |
| **年級** | 42 分鐘（1×） | 規劃四季：春耕、夏管、秋收、冬藏；追求人口與地標目標 | 四季切換、天氣權重、年度成就 |

### 1.2 正回饋鏈

```
鋪路 ─→ 建茅屋 ─→ 流民遷入（人口↑） ─→ 勞動力↑
  ↑                                        │
  │                                        ↓
民心↑ ←─ 水井／寺廟／學堂／茶館 ←─ 稅收／服務收入 ←─ 市集＋倉庫物流 ←─ 農田／生產建築
  │                                        │
  └────────── 人口解鎖新建築 ←──────────────┘
```

- **人口**是解鎖貨幣（`unlockPop`）：15 糧倉 → 20 市集 → 30 瓦房 → 40 採石場 → 50 茶館 → 60 貨棧／寺廟 → 70 茶園 → 80 學堂 → 90 酒坊 → 100 衙門 → 120 織坊 → 140 客棧 → 150 鐵礦場 → 160 宅院 → 180 鐵匠鋪 → 200 碼頭。完整表見 §4.3。
- **民心**是人口成長的油門：民心 ≥ 50 才會穩定遷入；≥ 70 遷入快、出生率上升；< 25 開始遷出。
- **糧食**是硬上限：缺糧時民心暴跌、人口停滯甚至流失。

### 1.3 前 10 分鐘腳本（1× 速度；實際秒數為約值）

| 時間 | 遊戲日 | 玩家動作 | 預期結果 |
|---|---|---|---|
| 0:00–0:30 | 第 1 日 | 看教學（可關閉）；觀察出生點附近地形（找草原／沃土／水） | 知道「道路→茅屋→農田」 |
| 0:30–1:00 | 第 1 日 | 從出生點向外鋪 8～12 格道路（32～48 兩） | 道路網成形，工具列顯示道路模式 |
| 1:00–1:40 | 第 1–2 日 | 道路兩側建**茅屋×2**（120 兩）；旁邊沃土建**農田×1**（120 兩） | 5 名流民抵達；茅屋開始入住；農田需 4 工人 |
| 1:40–2:30 | 第 3–5 日 | 建**水井×1**（60 兩）；再補茅屋至 5 座 | 人口約 8～14；民心 65+ |
| 2:30–4:00 | 第 6–8 日 | 人口 15 解鎖**糧倉**（160 兩）→ 建在農田與道路旁 | 農田產出開始集中，日結算有存糧 |
| 4:00–6:00 | 第 9–12 日 | 人口 20 解鎖**市集**（260 兩）→ 鋪路連接、放進住宅區 | 市民開始購物；市集貨架出現糧食 |
| 6:00–8:00 | 第 13–16 日 | 補**農田×1～2**、**水井**覆蓋新住宅；留意「農田缺工」提示 | 人口 22～28；糧食供給 > 需求 |
| 8:00–10:00 | 第 17–20 日 | 人口 30 解鎖**瓦房**（180 兩）→ 升級住宅；人口 40 解鎖**採石場** | 人口 30+；國庫仍 > 4000；完成第一個月報表 |

> **設計檢查點**：10 分鐘結束時，玩家應該已經：① 看懂三種需求；② 知道搬運工在運什麼；③ 至少觸發一次「缺糧／缺工／缺路」的具體提示；④ 知道下一步要往人口 40 的採石場前進。

### 1.4 玩家每 30 秒的決策清單

1. 現在最缺什麼？（糧食／勞動力／道路／倉儲／民心）
2. 手上 300～600 兩要花在哪？（房、田、市集、倉庫、服務）
3. 哪一格地形最適合？（沃土→田、林地→伐木、丘陵→採石／茶、臨水→碼頭）
4. 這條路要不要延伸？（連通性）
5. 稅率要不要動？（收入 vs 民心）
6. 要不要辦節慶？（成本／冷卻／時機）

## 2. 世界、地形與道路規則

### 2.1 地圖與地形

- 地圖 72×72，`tileIndex = y*width + x`；世界座標置中，格中心 `(x+0.5)*TILE - width*TILE/2`（`TILE=2`），一律用 `src/render/coords.ts` 的 helper，勿自行硬算。（✅ ARCHITECTURE §4）
- 地形與可建造性（✅ `TERRAIN_INFO`）：

| 地形 | 可建造 | 生產加成（本作建議實作） | 備註 |
|---|---|---|---|
| `grass` 平原 | ✅ | 無 | 通用建築 |
| `fertile` 沃土 | ✅ | **農田產量 ×1.3（+30%，✅ config 註記）** | 沿河分布 |
| `forest` 林地 | ✅ | **伐木場 ×1.3** | 樹木視覺、可伐木 |
| `hill` 丘陵 | ✅ | **採石場 ×1.25、茶園 ×1.2、鐵礦場 ×1.15** | 梯田視覺 |
| `mountain` 山地 | ❌（見 §3.8 例外） | 鐵礦場 ×1.3（若允許建） | 地圖邊緣 |
| `water` 水域 | ❌ | — | 碼頭需臨水 |
| `sand` 沙岸 | ✅ | 無（可作渡口／碼頭區） | 臨水 |

> 🔧 **實作方式**：以建築 footprint 內出現次數最多的地形判定加成（平手取中心格），在 `production.ts` 計算；不要在每一格重算。

### 2.2 世界生成規格（給 world-renderer 的可驗收條件）

1. **河流**：由北至南蜿蜒，寬度 1～2 格；**至少 2 處「淺灘／渡口」**（`sand` 或 `grass`，可鋪路），保證玩家能不靠橋跨越河道。
2. **湖泊**：1～2 個，面積 40～120 格，位於地圖中側或角落。
3. **山地／丘陵**：山地集中地圖邊緣（外框 8 格內），丘陵散布於平原交界。
4. **林地**：3～6 片，總面積 ≥ 400 格，其中至少 1 片距出生點 ≤ 15 格。
5. **沃土**：沿河兩岸帶狀分布，總面積 ≥ 250 格，出生點 12 格內至少 20 格。
6. **中央可建平地**：出生點周圍 20×20 範圍內 ≥ 300 格可建（非水／山／林亦可），且 `spawn` 本身可建。
7. **沙岸**：臨水自動生成，總面積 ≤ 5%。
8. **驗收**：用水／山以外的可建格佔比 ≥ 55%；任一 spawn 到地圖主要區域的道路連通性可成立。

### 2.3 道路規則

| 規則 | 內容 | 來源 |
|---|---|---|
| 造價 | **4 兩／格**（✅ `ROAD_COST`） | config |
| 維護 | **0 兩／月**（✅ `ROAD_UPKEEP`）；v1 不計道路維護 | config |
| 拆除退款 | **1 兩／格**（`floor(4 × 0.3)`，✅ `DEMOLISH_REFUND_RATE=0.3`） | config |
| 可鋪地形 | 可建造地形（草原／沃土／林地／丘陵／沙岸）；**不可鋪水域、山地**，不可疊在建築上 | placement |
| 鋪設方式 | 點擊單格＋**按住左鍵拖曳連續鋪設**（city-view 已支援） | 實作 |
| 連通判定 | 建築 footprint 的**正交外側任一格**為道路 → `connected = true`；斜角不算 | pathfinding |
| 未連通 | `connected = false` → 生產／服務／工人通勤全部停止（免路建築除外） | 設計 |
| 拆除道路 | 需重算所有建築連通性（`updateConnectedBuildings`） | placement |

> 🔧 **橋樑**：v1 不實作橋樑；以世界生成的「渡口淺灘」跨河。v1.1 可加木橋（水上道路格，造價 20 兩）。

### 2.4 建築臨路規則（給 placement.ts 的預設表）

`BuildingDef.needsRoad` 只有 `hut` 明確為 `false`；其餘未填。**建議 placement.ts 以類別推導預設，並以下表為準**（不改 config）：

| 建築 | 需臨路 | 理由 |
|---|---|---|
| 茅屋 `hut` | ❌ 否（✅ config `needsRoad:false`） | 開局第一棟不應被道路卡住 |
| 瓦房 `house`、宅院 `manor` | ✅ 是 | 居民需通勤、市集需送貨 |
| 所有生產建築（農田、茶園、伐木場、採石場、鐵礦場、酒坊、織坊、鐵匠鋪） | ✅ 是 | 工人通勤＋產出運出 |
| 糧倉 `granary`、貨棧 `warehouse` | ✅ 是 | 物流節點 |
| 市集 `market`、茶館 `teahouse`、客棧 `inn`、碼頭 `dock` | ✅ 是 | 商業營運 |
| 寺廟 `temple`、學堂 `school`、衙門 `yamen` | ✅ 是 | 公共服務 |
| 水井 `well` | ❌ 否 | 無工人、1×1 便民設施 |
| 涼亭 `pavilion` | ❌ 否 | 純裝飾 |

> ⚠️ **注意**：這與 `types.ts` 的註解「預設民居／商業／民生為 true」一致；但實作時務必把 `well`、`pavilion`、`hut` 列為例外，否則新手第一個水井放不下去會困惑。

### 2.5 擺放／拆除共通規則

- 銀兩不足 → 不可建（拒絕原因「銀兩不足」）。
- 人口不足 → 未解鎖建築顯示鎖頭與「人口 N 解鎖」。
- 地形不符 → 具體說明（「此地形不可建造」／「農田需建於沃土或平原」／「碼頭需臨水」）。
- 拆除退款 **30%**（✅）；拆除住宅時，居民變無家、工人失業（placement 已清理參照）。
- 拆除道路／建築後立刻重算連通性。

**季節／天氣倍率（✅ config）**

| 建築 | 春 | 夏 | 秋 | 冬 | 天氣加成 |
|---|---|---|---|---|---|
| 農田 `farm` | 1.2 | 1.1 | 1.35 | 0.3 | rain 1.2、snow 0.3、clear 1.05（cloudy 未列→用通用 `WEATHER_EFFECT`） |

> 🔧 **生產公式（生產建築通用）**
> ```
> workerRatio = (connected && active) ? min(1, workers.length / def.workers) : 0
> seasonMult  = def.production.seasonBonus?.[season] ?? SEASON_FARM_BONUS[season]
> weatherMult = def.production.weatherBonus?.[weather] ?? WEATHER_EFFECT[weather].farm
> terrainMult = 地形加成（§2.1；非生產地形為 1）
> amount      = def.production.amountPerDay × workerRatio × seasonMult × weatherMult × terrainMult
> 若需投入：先檢查本地庫存 → 不足則從連通倉庫調撥（§5.3）→ 仍不足則本日停產
> 產量受本地暫存上限 30 限制：amount = min(amount, 30 - inventory)
> ```
> 每日結算時一次算完（`tickProduction`），不需要每幀更新；`Building.productionProgress` 可用於生產動畫，v1 可忽略。

### 3.3 倉儲（storage）

| key | 名稱 | 尺寸 | 造價 | 維護/月 | 工人 | 解鎖人口 | 容量 | 可收資源 |
|---|---|---|---|---|---|---|---|---|
| `granary` | 糧倉 | 2×2 | 160 | 1 | 2 | 15 | 500 | 僅糧食 |
| `warehouse` | 貨棧 | 2×2 | 200 | 2 | 3 | 60 | 400 | 全部 |

> 🔧 **倉儲規則**
> - 每個建築的 `inventory` 是「本地庫存」；倉庫容量 = `storage.capacity`（合計所有資源）。
> - 生產建築本地暫存上限 **30**（所有資源合計）；滿了就停止生產，直到搬運工運走。
> - 糧食優先進糧倉；糧倉滿了才進貨棧。其他資源只進貨棧。
> - 市集是「貨架」不是倉庫：容量 250，只收**糧食／茶葉／酒／布帛**（見 §5.2）。

### 3.7 建築狀態與營運條件

| 狀態 | 判定 | 影響 |
|---|---|---|
| `connected` | 臨路規則（§2.4） | 未連通：生產／服務／工人分配停止；UI 顯示「未連通道路」 |
| 有工人 | `workers.length > 0` 且 `connected` | 效能 = 工人比例 |
| 缺工 | `workers.length < def.workers` | 產量／服務按比例打折；UI 顯示「工人 2/4」 |
| 缺料 | 需要投入但倉庫無庫存 | 停產；UI 顯示「缺糧食」等 |
| 滿倉 | 本地庫存 ≥ 30（生產）或 ≥ 容量（倉儲） | 停產／拒收；UI 顯示「暫存已滿，等待搬運」 |
| 服務中 | 服務建築有工人、有貨源、connected | 半徑內住宅獲得幸福／貨架 |
| 未營運 | `active=false`（預留） | 不生產、不服務 |

> 🔧 **`active` 欄位**：v1 由 `connected`＋工人推導即可；`active` 保留給「手動停業」或事件（火災／維修）使用，避免改型別。

### 3.8 地形限制的例外與工程建議

1. **鐵礦場 × 山地（必須處理）**：config 的 `ironMine.production.allowedTerrain = ['hill','mountain']`，但 `TERRAIN_BUILDABLE.mountain = false`，而 `placement.ts` 先檢查可建性、再檢查 `allowedTerrain` → **山地永遠蓋不了鐵礦場**。
   - 建議（不動 config，推薦）：在 `placement.ts` 對 `key === 'ironMine'` 特例允許 `mountain`（其餘建築維持不可建）。這也符合「山地可採鐵」的 `TERRAIN_INFO` 註記（✅ `mountain: note:'不可建造，可採鐵'`）。
   - 備選（需 Lead 改 config）：`allowedTerrain` 改為 `['hill']`，並調整 `TERRAIN_INFO.mountain.note`。
2. **加工建築的地形建議**：酒坊／織坊／鐵匠鋪在 config 中沒有 `allowedTerrain`，目前可蓋在林地、丘陵、沙岸。建議 `placement.ts` 額外限制為 **grass／fertile／sand**（視覺合理、避免與「林地／丘陵」的採集印象衝突）；此為 placement 規則，不改 config。
3. **農田的地形限制**：config 只允許 `fertile`／`grass`；林地／丘陵／沙岸不能蓋農田。世界生成（§2.2）必須在出生點 12 格內提供足夠的沃土／平原，否則新手會卡住。
4. **碼頭臨水**：`needsWater=true`，判定「footprint 外側 8 鄰域有水域」；碼頭不要求水深，任何水域格皆可（v1）。
5. **水域／山地其他用途**：v1 水域不可建造（除碼頭臨水）、山地不可建造（除鐵礦場特例）；🕒 v1.1 可加「渡口」「礦場平台」等特殊建築。
6. **不做地形改造**：v1 不支援填湖、移山、改造林地；worldgen 的一次性生成即為最終地形。

## 4. 市民與需求系統

### 4.1 市民生命週期

| 階段 | 規則 | 數值建議 |
|---|---|---|
| 開局流民 | 第 1 日若有地圖上尚無市民，生成 **5 名成年人**（16～40 歲），無家、失業，在地圖中央可建平地等待 | 🔧 `population.ts`；若 `GameState` 無 spawn 欄位，以 `(width/2, height/2)` 取代（建議 Lead 補 `spawnX/spawnY`） |
| 遷入 | 每棟住宅每日檢查空位；城市平均民心 ≥ 50 時，每個空位有 `p = clamp((民心-45)/100, 0, 0.4)` 機率遷入；無家流民優先入住 | 🔧 每日最多遷入 `3 + floor(pop/50)` 人，避免暴增 |
| 出生 | 民心 ≥ 65 且住宅有空位：每日每 100 居民約 0.4 名新生 | 🔧 因遊戲年僅 84 日，新生兒**直接以 16 歲青年出現**（象徵二代成年），避免等 16 年 |
| 死亡 | 每日機率 `0.0004 + max(0, age-55) × 0.00015`；死亡從住宅與工作地移除 | 🔧 平均壽命約 65～75 遊戲歲 |
| 遷出 | 民心 < 25 連續 3 日 → 每日 10% 機率 1 人搬走；無家者 5 日後離開 | 🔧 遷出理由寫入 log（「民不聊生，百姓出走」） |
| 上限 | `citizens.length ≤ 800`；住宅容量不足時停止遷入 | 🔧 效能保護 |

- 姓名：`SURNAMES`＋`GIVEN_NAMES` 隨機組合（1～2 字名）；性別隨機；`look` 0..1 供衣色／髮色；年齡、性別、look 都在生成時固定（存檔相容）。
- 勞動年齡：**16～60 歲**；兒童與老人不工作但仍消耗糧食。`stats.unemployed` 目前以 age ≥ 14 判定（economy-dev 維護），建議統一為 16 並在回報中說明。

### 4.2 三大需求（食物／日用品／文化）

`CitizenNeeds` 三個 0..100 數值，每日結算一次（`newDay`）：

| 需求 | 滿足條件 | 每日變化 | 飢餓／欠缺後果 |
|---|---|---|---|
| `food` 食物 | 住宅在市集半徑內且市集有糧食庫存 → 滿足；否則若**全城糧食庫存 > 0** → 部分滿足（自家囤糧） | 滿足 +12；部分 +6；不足 -18 | 連續 2 日不足 → 觸發「缺糧」提示；全城無糧 → 饑荒（另見 §6.6） |
| `goods` 日用品 | 住宅在市集半徑內，且市集有茶葉／酒／布帛任一 → 滿足 | 滿足 +9；否則 -12 | 影響民心與遷入 |
| `culture` 文化 | 住宅在寺廟或學堂半徑內 → 滿足（兩者不疊加） | 滿足 +6；否則 -7 | 影響民心與遷入 |

> 🔧 **設計理由**：Pharaoh／Anno 證明需求要分層，Banished 證明玩家最怕「不知道為什麼」。本作把「食物」做成可全域保底（避免開局沒有市集就餓死），把「日用品／文化」做成市集與公共服務的價值所在。

### 4.3 幸福度（民心）公式

每日對每位市民計算 `target`，再平滑逼近：

```
base = 45
foodScore    = needs.food    × 0.25      // 0..25
goodsScore   = needs.goods   × 0.15      // 0..15
cultureScore = needs.culture × 0.10      // 0..10
serviceBonus = 住宅半徑內服務加成合計（同類型取最近一棟，上限 20）
               well +3、pavilion +2、temple +8、school +5、teahouse +6、inn +3
               （茶館／客棧需有營運與貨源才算）
taxPenalty        = taxRate × 100 × 0.35          // 10% → −3.5
unemploymentPen   = (workId < 0 && 16≤age≤60) ? 8 : 0
homelessPen       = (homeId < 0) ? 15 : 0
weatherBonus      = WEATHER_EFFECT[weather].happiness   // +2 / 0 / −2 / −4
festivalBoost     = max(0, 12 − (totalDays − finance.lastFestivalDay))   // 節慶後 12 日線性衰減
bankruptcyPen     = finance.treasury < 0 ? 5 : 0

target = clamp(base + foodScore + goodsScore + cultureScore + serviceBonus
             − taxPenalty − unemploymentPen − homelessPen + weatherBonus
             + festivalBoost − bankruptcyPen, 0, 100)

// 每日平滑：下降快、上升慢，讓危機有感覺
happiness += clamp(target − happiness, −6, +4)
```

**民心分級（UI 用）**

| 民心 | 稱呼 | 顏色 | 行為 |
|---|---|---|---|
| 70–100 | 安居樂業 | 青綠 | 遷入快、出生率上升 |
| 40–69 | 尚可溫飽 | 金 | 穩定遷入 |
| 25–39 | 民怨漸生 | 橙 | 遷入停滯、偶有遷出 |
| 0–24 | 民不聊生 | 朱紅 | 大量遷出、人口停滯 |

> 🔧 城市顯示的民心 = `stats.happiness` = 全體市民平均；無市民時顯示 70。

### 4.4 行為狀態機（`citizen.state`）

```
home ──(06:00 起床，07:00 上班)──▶ walking ──到達──▶ working
  ▲                                                    │
  │                                        (17:00 下班，隨機購物)
  │                                                    ▼
  └──────────── home ◀──到達── shopping ◀──(有市集/貨品)── walking
idle：無家可歸、失業、路徑失效時；每小時重試
```

| 時段（遊戲時） | 行為 |
|---|---|
| 06:00–07:00 | 起床（home）；若失業可 idle |
| 07:00–08:00 | 前往工作地（walking） |
| 08:00–17:00 | 工作（working；建築不存在／未連通則重新找工作） |
| 17:00–18:00 | 30% 機率去市集購物（shopping），否則回家 |
| 18:00–22:00 | 在家（home）；可顯示燈籠 |
| 22:00–06:00 | 睡眠，不移動（效能與視覺秩序） |

- **通勤**：`findRoadPath(home 臨路格 → 工作地臨路格)`；`path` 存格 index 陣列，`pathProgress` 浮點；每幀依移動速度推進。
- **購物**：目標為最近且有貨的市集；抵達時 `citizen.money -= 1.5`、`market.incomeThisMonth += 1.5`（**不直接進國庫**，避免與月結服務收入重複計算）；市集庫存已在每日服務結算（§5.2）扣除，購物動作**不重複扣庫存**，只作為視覺與個人記帳；之後回家。
- **路徑失效**（拆除道路／建築）：目前狀態改 `idle`，下一小時重試。
- `x/y` 為格座標浮點，供 `render/citizens.ts` 插值；市民在同一格內也應有微小偏移（look 種子），避免完全重疊。

### 4.5 移動速度與天氣（重要數值修正）

| 對象 | 建議速度 | 換算（1×，48 遊戲分/真實秒） | 說明 |
|---|---|---|---|
| 市民 | **0.06 格／遊戲分鐘** | ≈ 2.9 格／真實秒；跨 72 格約 25 秒 | 🔧 |
| 搬運工（Cart） | **0.10 格／遊戲分鐘** | ≈ 4.8 格／真實秒 | 🔧 |
| 天氣倍率 | `WEATHER_EFFECT[weather].move`（✅ 晴 1／陰 1／雨 0.72／雪 0.6） | — | config |
| 夜間（22:00–06:00） | ×0.9（市民）；搬運工 v1 可停工或 ×0.9 | — | 🔧 |

> ⚠️ **必須修正的規格落差**：`docs/ARCHITECTURE.md` §6 寫「市民移動速度約 1.2 格/遊戲分鐘」。依 `GAME_MINUTES_PER_SECOND = 48` 換算，這是 **57.6 格/真實秒**，會讓市民瞬間跨圖。建議 citizen-dev／logistics-dev 採用上表（0.06／0.10 格/遊戲分鐘），並在回報中告知 Lead。

## 5. 物流與生產鏈

### 5.1 物流總圖

```
 生產建築（農田/茶園/伐木/採石/鐵礦/酒坊/織坊/鐵匠鋪）
      │  每日產出 → 本地暫存（上限 30）
      ▼
  搬運工（Cart，沿道路，受天氣影響）
      │  grain                    │  其他資源
      ▼                           ▼
   糧倉（500，只收糧） ──溢出──▶ 貨棧（400，全收）
      │                           │
      │  市集補貨（grain）         │  市集補貨（茶/酒/布）
      ▼                           ▼
             市集貨架（250） ──供貨──▶ 民居（半徑 9）
                  │
                  ├──▶ 茶館（消耗茶葉 1.2/日）
                  ├──▶ 客棧（消耗酒 1.2/日）
                  ▼
               碼頭（出口多餘貨物換銀）

  酒坊 ←─ 糧食 5/日 ── 糧倉／貨棧（調撥）
  鐵匠鋪 ←─ 鐵礦 2.5/日 ── 貨棧（調撥）
```

### 5.2 搬運工（`state.carts`）派遣規則

| 規則 | 內容 |
|---|---|
| 檢查頻率 | 每 **30 遊戲分鐘**（0.625 真實秒 @1×）掃描一次，避免每幀派車 |
| 派遣條件 | 生產建築 `connected`、有工人、本地庫存 ≥ 8 |
| 目的地 | 糧食 → 最近的糧倉（容量足夠），否則貨棧；其他 → 最近的貨棧（容量足夠） |
| 單趟數量 | 依資源別：糧食 20、木材／石料 15、鐵礦 12、茶／酒／布 10、工具 8；`amount = min(capacity, 本地庫存)` |
| 上限 | 同時最多 **40 台**；超過則排隊（優先最舊的待運庫存） |
| 路徑 | `findPathBetweenBuildings`；無路徑 → 不派遣、記錄一次提示「道路未接通」 |
| 移動 | 沿 path 以 0.10 格/遊戲分鐘 × 天氣倍率移動；`x/y` 插值供渲染 |
| 抵達 | 轉移貨物 → `phase` pickup→deliver → `done=true` → 移除；貨物計入 `stats.goodsInTransit` |
| 容量不足 | 目的地全滿 → 不派遣；生產建築本地暫存滿 30 後停產（形成壓力，促使玩家加倉庫） |
| 失效清理 | 拆除建築時移除相關 carts（placement 已做） |

**市集補貨（第二段物流）**

- 每棟市集每日檢查貨架目標：**糧食 120、茶葉 20、酒 15、布帛 20**（容量 250；`accepted` 僅限這四種）。
- 不足時派搬運工向最近糧倉（糧食）或貨棧提貨；單趟量同上。
- 市集貨架比例是玩家判斷「物流是否健康」的主要指標，UI 必須顯示。

**每日服務結算（newDay；建議 economy-dev 在 `production.ts` 或新增 `services.ts` 實作）**

1. 對每座**營運中**（connected＋有工人）的市集，統計半徑 9 格內住宅的居民人口 `served`：
   - 扣糧食 `min(市集糧食庫存, served × 1)`（每人每日 1 單位）；不足時按比例決定住宅食物需求滿足度（§4.2）。
   - 扣日用品 `served × 0.15`，從茶葉／酒／布帛中**優先消耗存量最多者**；無任何日用品則該項不扣、日用品需求不滿足。
2. 對每座營運中的**茶館**扣茶葉 1.2／日；營運中的**客棧**扣酒 1.2／日。自身庫存不足時，v1 直接從最近連通貨棧調撥（同 §5.3 規則）；仍不足 → 當日不營業（無收入、無幸福加成）。
3. 以上消耗若在 `tickProduction` 之後才結算，需確保不與生產投入重複扣同一批糧食（市集與酒坊吃的糧食來源不同：市集吃貨架、酒坊吃倉庫）。
4. 供貨結果對應到 §4.2 的 `food`／`goods` 需求更新；市民購物（§4.4）只是視覺與 `market.incomeThisMonth` 的記錄，**不重複扣庫存**（庫存已在每日服務結算扣除）。

**碼頭出口（第三段物流）**

- 每 **3 遊戲日**（`totalDays % 3 === 0`）結算一次；碼頭需 `connected`、工人 ≥ 3。
- 從最近貨棧取「超過保留量」的貨物出口；保留量：糧食 300、茶葉 20、酒 15、布帛 20、木材 50、石料 50、鐵礦 30、工具 10。
- 單次上限 20 單位／碼頭；售價 = `RESOURCES[key].price × 0.8`；收益**記入 `finance.incomeThisMonth`（月底與其他收入一起入賬，不得直接改 treasury）**，並寫 log。
- 建議：出口優先工具（8 兩）> 酒（5）> 茶（4.5）> 布（4）> 鐵（4）> 石（2.6）> 木（2）。

### 5.3 生產投入的調撥（酒坊／鐵匠鋪）

- 每日生產前先扣本地庫存；不足時，從**最近的連通貨棧**（糧食可從糧倉）直接調撥所需量，扣倉庫庫存並加至生產建築。
- v1 不派搬運工做這件事（減少複雜度）；v1.1 可改成真正的搬運工任務，讓「原料進廠」也可視化。
- 若倉庫也無庫存 → 本日停產，UI 顯示「缺糧食／缺鐵礦」，並在 3 日內只提示一次（避免洗版）。

### 5.4 生產鏈與吞吐量表

| 資源 | 生產建築 | 滿工人日產 | 消耗者 | 消耗速率 | 出口參考價 |
|---|---|---|---|---|---|
| 糧食 `grain` | 農田 | 14 | 市民（1/人/日）、酒坊（5/日） | 100 人＝100/日 | 1.2 |

## 6. 財政系統

### 6.1 設計原則

- 國庫決定「能不能蓋新建築」；不支付市民工資，避免「稅收→工資→消費→稅收」的雙重計算。
- 市民的 `money` 是抽象道具：就業者每日象徵性獲得 2 兩（不由國庫扣），購物時支出；用於「有沒有錢買日用品」的判定，不影響國庫。
- 收入四來源：**人頭稅、田賦、商稅、服務收入（含碼頭出口）**；支出：**維護費＋建造／節慶等一次性支出**。

### 6.2 每月結算公式（實作於 `finance.ts`，常數放在檔案內）

```ts
const D = DAYS_PER_MONTH;                    // 7
const tax = finance.taxRate;                 // 0..0.2
const taxMult = hasActiveYamen ? 1 + 0.15 : 1;   // config service.taxBonus

// 1) 人頭稅：100% 稅率時每人每月 8 兩（預設 10% → 0.8 兩/人/月）
const headTax = stats.population * tax * 8;

// 2) 田賦：100% 稅率時每塊農田/茶園每月 40 兩（10% → 4 兩/塊/月）
const landTax = (farmCount + teaFarmCount) * tax * 40;

// 3) 商稅：100% 稅率時每棟市集/茶館/客棧/碼頭每月 60 兩（10% → 6 兩/棟/月）
const shopTax = (marketCount + teahouseCount + innCount + dockCount) * tax * 60;

// 4) 服務收入：incomePerDay × 7 × util（util = 人力 × 覆蓋 × 貨源，0..1）
const serviceIncome = sumServiceBuildings(incomePerDay * D * util);

// 5) 當月收入（碼頭出口已在發生時記入 incomeThisMonth，月底一次入賬）
const income = (headTax + landTax + shopTax) * taxMult
             + serviceIncome
             + finance.incomeThisMonth;

// 6) 維護費：唯一在月底才扣的支出
const operating = totalUpkeep(state.buildings);

// 7) 建造費／節慶已在 placement/main 即時扣款，累計在 expenseThisMonth；
//    月底只做報表，不再重複扣 treasury（避免雙重支出）
const capital = finance.expenseThisMonth;

finance.treasury += income - operating;           // 收入入賬、維護費扣款
finance.lastMonthIncome = income;
finance.lastMonthExpense = operating + capital;   // 報表：營運＋資本支出
finance.history.push({
  year, month,
  income,
  expense: operating + capital,
  balance: income - operating - capital,
  population: stats.population,
  happiness: Math.round(stats.happiness),
});
if (finance.history.length > 24) finance.history.shift();
finance.incomeThisMonth = 0;
finance.expenseThisMonth = 0;
// 同時把所有建築的 incomeThisMonth / expenseThisMonth 歸零（供下月 UI 統計）
for (const b of state.buildings) { b.incomeThisMonth = 0; b.expenseThisMonth = 0; }
```

> **為什麼 treasury 只減 operating？**
> 建造費與節慶費在 `placeBuilding`／`holdFestival` 時已即時從國庫扣除，並累計到 `finance.expenseThisMonth`；若月底再扣一次就是雙重支出。月報表仍要呈現「營運＋資本」全貌，因此 `history.balance` 可能與國庫實際變化不同（差額＝本月已在月內支付的資本支出）。UI 建議在支出欄 tooltip 註明「含本月建造支出 N 兩」。

**服務 util 計算**

| 建築 | `coverage`（服務容量） | 額外係數 |
|---|---|---|
| 市集 | 半徑內住宅人口 / 200 | `min(1, 市集糧食 / (服務人口×2))`（可選） |
| 茶館 | 半徑內住宅人口 / 150 | `min(1, 可用茶葉 / (1.2×7×coverage))` |
| 客棧 | 半徑內住宅人口 / 250 | `min(1, 可用酒 / (1.2×7×coverage))` |
| 碼頭 | 當月有出口即 1 | — |
| 寺廟／學堂／衙門／水井／涼亭 | 不計收入（只影響幸福與稅收加成） | — |

- `staffing = def.workers > 0 ? clamp(workers.length / def.workers, 0, 1) : 1`。
- **注意**：市集、茶館、客棧的貨物消耗（茶 1.2/日、酒 1.2/日、市集糧食）由每日服務結算扣庫存，不重複計入成本；若無貨，該日 util 降為 0。

### 6.3 收支試算（預設稅率 10%、無破產、無節慶）

| 階段 | 人口 | 住宅 | 生產 | 商業／服務 | 收入/月 | 維護/月 | 淨額/月 |
|---|---|---|---|---|---|---|---|
| 開局 | 20 | 茅屋×5 | 農田×2、伐木×1 | 市集×1、糧倉×1 | 約 31 | 5 | **+26** |
| 初期 | 60 | 茅屋×8、瓦房×4 | 農田×4、伐木×1、採石×1 | 市集×1、糧倉×1、貨棧×1 | 約 74 | 12 | **+62** |
| 中期 | 120 | 瓦房×10、宅院×2 | 農田×9、茶園×1、伐木×1、採石×1、織坊×1、酒坊×1 | 市集×2、糧倉×1、貨棧×2、茶館×1、寺廟×1、學堂×1、衙門×1 | 約 198 | 36 | **+162** |
| 後期 | 300 | 瓦房×25、宅院×5 | 農田×20、茶園×2、伐木×2、採石×2、織坊×2、酒坊×1、鐵礦×1、鐵匠×2 | 市集×4、糧倉×2、貨棧×4、茶館×2、客棧×1、寺廟×1、學堂×1、衙門×1、碼頭×1 | 約 640（另加出口） | 76 | **+564** |

> 試算假設：勞動力 = 人口 × 65%（16～60 歲），服務建築人力係數 = min(1, 勞動力/職位總數)；衙門加成 15%。實際遊戲中勞動力不足會壓低服務收入。
> **解讀**：本作金錢在中後期會趨於寬裕，這是刻意的——真正的成長瓶頸是勞動力、道路、倉儲、民心。若希望後期仍緊張，見 §12.3 的建議調整。

### 6.4 稅率

- 範圍 0～20%，UI 以 1% 為步進；即時生效，次月結算體現。
- 稅率對民心的懲罰：`taxRate × 100 × 0.35`（10% → −3.5；20% → −7）。
- 建議甜蜜點 **8%～12%**；15% 以上需靠寺廟、茶館、節慶、水井等服務加成抵消。
- 0% 稅率：民心 +0（無懲罰），但沒有收入；適合截圖／沙盒。

### 6.5 節慶（`holdFestival`，主程式已實作）

| 項目 | 目前實作（✅ config／main.ts） | 設計說明 |
|---|---|---|
| 花費 | 300 兩 | 一次性支出，計入 `expenseThisMonth` |
| 冷卻 | 20 日 | `finance.lastFestivalDay` |
| 效果 | 全體市民 happiness +12（上限 100） | 另有 `festivalBoost`：之後 12 日幸福目標逐日衰減 +12→0 |
| 建議調整 | 花費改為 `200 + 人口 × 1.5`（取整到 10，上限 1200）；冷卻 14 日 | ⚠️ 需 Lead 改 `FESTIVAL_COST`／`main.ts`；見 §12 |

### 6.6 糧食安全與冬季壓力

- `stats.foodStored` = 所有建築 `inventory.grain` 合計；`stats.foodPerDay` = 人口 × 1（✅ STATS 現值）。
- UI 顯示「存糧天數 = foodStored / max(1, foodPerDay)」；建議維持 ≥ 10 日；**入冬前 ≥ 21 日**。
- 冬季 21 日、人口 100：需求 2100 糧；9 座農田在冬季（混合天氣）約產 680 糧 → 入冬前需存 **≥ 1420 糧**。
- 容量規劃：糧倉 500／貨棧 400／市集 250。人口 100 建議 **3 座糧倉＋1 座貨棧＋1 座市集**（合計 2150）以度冬。
- 缺糧事件：全城糧食 = 0 且當日需求不足 → toast「糧倉見底，百姓挨餓！」＋民心 −10/日；連續 5 日 → log「饑荒」並加速遷出。

### 6.7 月報表與統計

- `finance.history` 保留最近 **24 個月**；UI 顯示最近 8 個月。
- 月報表欄位：年月、收入、支出、盈餘、人口、民心；支出以「維護費＋建造支出＋節慶」合計呈現，建造支出建議在 tooltip 標示「含資本支出」。
- 建議 `stats` 擴充（需 Lead 同意）：`foodDays`、`housingVacancy`、`avgWorkerRatio`；未擴充前 UI 以現有欄位推算。

### 7.2 晝夜

| 時段 | 效果 |
|---|---|
| 05:00–06:00 | 黎明；天色由深藍轉暖 |
| 06:00–07:00 | 日出；市民起床 |
| 07:00–17:00 | 工作時段；晴天日光最強 |
| 17:00–18:00 | 黃昏；下班／購物 |
| 18:00–19:00 | 日落；燈籠逐戶亮起 |
| 19:00–22:00 | 夜晚；市民在家，可看到燈火 |
| 22:00–05:00 | 深夜；市民不移動，環境轉暗（星空／月光） |

- 🔧 夜間市民移動速度 ×0.9；搬運工可持續運作（或 v1.1 改為夜間停工）。
- 生產與需求仍以「日」為單位結算，不因晝夜改變產量（避免玩家被迫等到白天）。
- `environment.ts` 依 `clock.hour`、`season`、`weather`、`tempC` 平滑過渡天空色、太陽／月亮方位、霧、雨雪粒子；室內環境另由 `interior.ts` 處理。

### 7.3 四季（✅ `SEASON_FARM_BONUS`、`SEASON_TEMP`、`SEASON_INFO`）

| 季節 | 月份 | 基礎氣溫 | 農作倍率（通用／農田） | 視覺 | 玩家策略 |
|---|---|---|---|---|---|
| 春 `spring` | 1–3 | 17°C | 1.15／1.2 | 嫩綠、花開 | 春耕、擴張農田 |
| 夏 `summer` | 4–6 | 30°C | 1.05／1.1 | 濃綠、日照長 | 管理勞動力、備倉 |
| 秋 `autumn` | 7–9 | 19°C | 1.25／1.35 | 金黃、落葉 | **秋收、囤糧過冬** |
| 冬 `winter` | 10–12 | 3°C | 0.35／0.3 | 雪白、枯枝 | 冬藏、修屋、辦節慶 |

- 季節每 3 個月切換一次（21 日）；`seasonOfMonth` 的邊界：1–3 春、4–6 夏、7–9 秋、10–12 冬（✅）。

### 7.4 天氣（✅ `WEATHER_WEIGHTS`、`WEATHER_EFFECT`）

| 天氣 | 春 | 夏 | 秋 | 冬 | 農作倍率 | 移動倍率 | 民心 | 備註 |
|---|---|---|---|---|---|---|---|---|
| 晴 `clear` | 42 | 55 | 45 | 30 | 1.05 | 1.0 | +2 | 適合農耕 |
| 陰 `cloudy` | 30 | 25 | 32 | 38 | 1.0 | 1.0 | 0 | 氣溫微降 |
| 雨 `rain` | 28 | 20 | 23 | 7 | 1.2 | 0.72 | −2 | 行人變慢、農作滋潤 |
| 雪 `snow` | 0 | 0 | 0 | 25 | 0.3 | 0.6 | −4 | 僅冬季；農作停擺 |

**天氣持續時間（⚠️ 建議調整 `time.ts`）**

- 目前：`90 + random×240` 遊戲分鐘（90–330 分 ≈ **1.9–6.9 真實秒** @1×），天氣變化過快、視覺與心情來不及感受。
- 建議：`300 + random×420` 遊戲分鐘（300–720 分 ≈ **6.3–15 真實秒** @1×，約 5–12 遊戲小時）；冬季可再 ×0.8（暴雪持續較短但更強）。
- `weatherIntensity` 平滑（目前 25 分鐘 → 建議 40 分鐘）；氣溫平滑（目前 45 分鐘 → 建議 60 分鐘）。
- **雪只可能在冬季**：time.ts 已處理（季節切換時若天氣不合理會重擲）；季節權重也將非冬季的雪權重設為 0。

### 7.5 氣溫

- `tempC` = 季節基礎 + 日夜正弦（±5°C，9 時為基準）+ 天氣修正（晴 +1、陰 −2、雨 −2、雪 −8），平滑逼近。
- 冬季 3°C、雪天可到 −10°C 左右；UI 顯示整數與天氣 emoji。
- 氣溫目前不直接影響玩法（可作為 v1.1 事件：嚴寒使民心額外 −2、木材消耗增加）。

### 7.6 晝夜／四季／天氣對玩法影響總表

| 倉儲（糧倉／貨棧） | 各資源存量與容量條；最近入庫／出庫（v1.1） | 糧囤、麻袋、貨架、木箱、帳冊 |
| 商業（市集／茶館／客棧／碼頭） | 貨架庫存；服務半徑內人口；本月收入；缺貨項目；碼頭另顯示最近出口 | 攤位旗幡、茶桌、酒旗、櫃台、碼頭木棧與貨物 |
| 民生（寺廟／學堂／衙門） | 服務半徑；覆蓋住宅數；幸福加成；衙門顯示稅收加成 | 佛龕香爐、書案書架、公案匾額與衙役 |
| 水井／涼亭 | 服務半徑；覆蓋住宅數 | 井欄、水桶、石桌石凳、燈籠 |

### 8.3 室內可用操作（v1）

- 返回城市（必要）。
- 拆除此建築（必要；危險操作需二次確認）。
- 查看居民／工人名單（唯讀；v1 不做點擊追蹤市民）。
- 🕒 v1.1：點擊市民 → 關閉室內並在城市中選中該市民（需要 actions 擴充）；「巡查」按鈕：每日一次，花 20 兩，該建築幸福 +2（需 Lead 擴充 action）。
- 室內**不可建造、不可調整稅率、不可存檔以外的面板操作**（保持介面乾淨）。

### 8.4 室內體驗要求

1. 相機取景：斜俯視、看得到主要家具與門口；建築越大，相機越遠。
2. 光線：暖色油燈＋窗光；白天窗光強、夜晚燈籠成為主光；`update` 加入燈火微動（閃爍頻率 2～4 Hz、幅度小）。
3. 音效：v1 可無（不新增依賴）；若日後加，以 WebAudio 合成環境音。
4. 人物象徵：以低多邊形人偶或剪影表示居民／工人，數量依實際人數（上限 8 個，其餘用文字名單）。
5. 效能：室內場景物件 < 200 draw call；共用 geometry／material；離開即 dispose。

### 8.5 室內與情感的連結（設計目標）

- 玩家點進一間茅屋，看到「王小花，23 歲，農夫，幸福 48，食物不足」——這比「民心 48」更有說服力。
- 因此**市民名字要出現在室內與資訊面板**，且狀態（工作、購物、在家）要能對應城市中的走動身影。
- 不要讓室內只是靜態展示：庫存、工人、缺料、幸福都要是真實 `GameState` 的投影。

### 9.1 資訊層級原則

1. **永遠可見**（頂欄）：日期時辰、季節天氣溫度、國庫、人口、民心、速度、面板入口。

| 類別 | 建議 |
|---|---|
| 色票 | 宣紙 `#efe6d3`、紙暗 `#e2d5bd`、墨 `#2b2620`、朱紅 `#a53f37`、金 `#c8a04a`、青 `#5f7f63`、文字亮 `#f4ead7`（✅ `COLOR`） |
| 字體 | `"Noto Serif TC", "Songti TC", "SimSun", serif`；數字用系統等寬；**不載入外部字型** |
| 材質 | CSS 漸層＋`repeating-linear-gradient` 做宣紙纖維；SVG 畫雲紋／回紋／朱印邊框 |
| 邊框 | 墨線 1px＋外層淡墨 2px；卡片圓角 2～3px（古風不宜大圓角） |
| 陰影 | 淡墨投影（`rgba(43,38,32,.18)`）；避免現代藍紫陰影 |
| 動畫 | 面板淡入 160ms、toast 進出 200ms、按鈕 hover 上浮 1px；**克制**，不做大幅位移 |
| 圖示 | 文字印章（華、營、財…）＋CSS/SVG 自繪；不使用外部圖片 |
| 無障礙 | 文字對比 ≥ 4.5:1；按鈕 focus 可見；`aria-label`；Esc 關閉 modal |

### 9.12 效能與更新策略

- `GameUI.update(state)` 每幀被呼叫：**不得**每幀重建 DOM。
  - 頂欄：只更新變動的文字／class（比較上次值）。
  - 左右面板：以 `ui.revision`、`ui.selectedId`、`ui.tool`、`ui.buildCategory` 做 diff。
  - modal：以開啟狀態＋`ui.revision` 重建；滑桿拖曳時只更新文字，不全量重建。
  - toast：事件驅動（`store.on('toast')`），不輪詢。
- 事件用 root 上的事件委派（`data-*` 屬性），避免每幀重綁 listener。
- 市民／搬運工渲染用 InstancedMesh；UI 不顯示個別市民的 DOM 節點（僅面板名單前 8～12 人）。

### 10.4 地標建造（🕒 v1.1，Foundation／Emperor 借鏡）

- 可集資建造「鼓樓、寶塔、城隍廟、牌坊」等大型地標：
  - 造價 1500～5000 兩＋大量木材／石料（需建材系統）。
  - 建造期 30～60 遊戲日，期間需要工人。
  - 完成後提供全城光環（民心 +5～10、稅收 +5%、吸引力解鎖觀光客）。
- v1 先以寺廟／衙門／學堂作為「準地標」滿足視覺與功能需求。

### 10.5 長期挑戰（給想繼續玩的玩家）

1. 在人口 300 時仍維持民心 ≥ 80、存糧 ≥ 21 日。
2. 冬天不發生饑荒（連續 3 個冬季）。
3. 全城無失業、無無家可歸。
4. 年稅收 ≥ 500 兩且國庫 ≥ 10,000 兩。
5. 建成「古城八景」：8 座涼亭、3 座寺廟、2 座學堂、1 座衙門、1 座碼頭（v1 可用 log 記錄）。

## 12. 數值平衡與 `config.ts` 建議

### 12.1 平衡總原則

1. 開局 6000 兩＋預設 10% 稅率：前 10 分鐘不該破產，也不該「錢多到不用想」。
2. 1 座農田養 14～18 人，4 名工人；勞動力（16～60 歲）是早期最硬的瓶頸。
3. 冬季 21 日、產量接近停擺：秋收後必須囤糧，倉儲容量是真需求。
4. 民心主要由食物、日用品、文化、服務、稅率決定；節慶是短期補救。
5. 金錢後期寬裕是刻意設計；若需要緊張感，調整 §12.3 的項目，而不是亂砍收入。

### 12.2 必須保持一致、不建議更動的數值（✅）

## 附錄 C：核心資料流（文字版）

```
[玩家輸入] --GameActions--> main.ts
  ├─ setTool/applyToolAt --> placement.ts（扣款、改 tiles、連通重算）
  ├─ select/enterBuilding --> ui（selectedId / mode / interiorId）
  ├─ setTaxRate/holdFestival --> finance（treasury、expenseThisMonth、lastFestivalDay、happiness）
  └─ save/load/newGame --> core/save.ts、core/new-game.ts --> store.setState（reset 事件）

[每幀] main.ts：Simulation.update(state, dt, ctx)
  └─ advanceClock（time.ts）
       ├─ newDay  --> updateConnectedBuildings + tickProduction + tickPopulation
       │              ├─ production：讀 workers / inventory / 地形 / 季節 / 天氣（寫 inventory）
       │              ├─ population：遷入／出生／死亡／就業（寫 citizens、buildings）
       │              └─ citizens（每日需求結算在 newDay；移動每幀）
       ├─ newMonth --> monthlyFinance（稅收、服務收入、維護費、history）
       └─ newYear --> log／事件（v1.1）
  ├─ tickCitizens（每幀移動、購物、狀態機）
  ├─ tickLogistics（每幀搬運工移動；每 30 遊戲分派遣；每 3 日碼頭）
  ├─ updateStats（每幀）
  └─ CityView.frame()：environment → terrain → roads → buildings → citizens → render
  └─ ui.update(state)（diff）

[物流資料]
  building.inventory（生產暫存 30 / 倉庫容量 / 市集貨架 250）
  cart{resource, amount, fromId, toId, path, pathProgress, phase, done}
  stats.goodsInTransit（每幀由 carts 加總）

[UI 讀取]
  stats（人口／就業／糧食／民心／淨收入／物流中）
  finance（treasury／taxRate／history／lastFestivalDay）
  clock（日期／天氣／溫度／季節）
  buildings（每棟狀態：connected／workers／residents／inventory／incomeThisMonth）
  log（最近 3 條）
```
